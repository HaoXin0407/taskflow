# TaskFlow 环境配置指引（JDK 17 + IDEA 2025.3.3）

> 本文档针对 IDEA 2025.3.3 + Maven 3 + Spring Boot 3.2 的配置。
> 踩过的坑都在下面标注了，照着做能少走弯路。

## 二、必做配置（4 处，缺一不可）

### 配置 1：Project SDK

```
File → Project Structure → Project
  ├─ SDK:  Add SDK → JDK 17
  │        路径：C:\Program Files\Java\latest\jdk-17.0.20.101-hotspot
  │        （点Add SDK 前要勾选 Download JDK 也可以，但本机已装好，直接选目录更快）
  │
  └─ Language level: 17 - Sealed types, always-strict floating-point semantics
```

> ⚠️ **常见错误**：Language level 选成 21 或更高，
> 编译时会报`class file has wrong version`。

### 配置 2：Maven Runner JRE（最容易漏）

```
File → Settings → Build Tools → Maven → Runner
  └─ JRE: 选 17 (Project JDK) 或 jdk-17.0.20.101-hotspot
```

> ⚠️ **这是最常见的坑**。上面配了 Project SDK 但这里还是 25 的话，
> Maven 依然会用 JDK 25 跑，表现就是各种莫名其妙的插件异常。

### 配置 3：Maven home path（解决 Guice 报错的关键）

```
File → Settings → Build Tools → Maven
  └─ Maven home path:
       从  Use Maven Wrapper   ↓改为
         Bundled (Maven 3)
```

**为什么必须改**：IDEA 默认选 `Use Maven Wrapper`，会去连外部 Maven 3.9.x，
而 IDEA 内置的 maven3-server 期望 3.10.x 的组件布局，两者不兼容，
依赖注入容器创建失败，报：

```
[Guice/MissingImplementation]: No implementation for ArtifactHandlerManager was bound
```

> 这是 IDEA 2025.x + Maven Wrapper 的已知兼容问题，
> 与项目代码无关，与 JDK 版本也不是主因。

配置完点右上角 **🔄 Reload All Maven Projects**。

### 配置 4：Maven Importer JDK

```
File → Settings → Build Tools → Maven → Importing
  └─ JDK for importer: 17
```

## 三、可选优化

### 3.1 修改 JAVA_HOME（推荐，避免命令行踩坑）

当前 `JAVA_HOME` 指向 D 盘的 JDK 25。如果你在 CMD/PowerShell 里用 maven，
会默认用 JDK 25，容易出问题。

改法（管理员 PowerShell）：

```powershell
# 先删掉旧的
[Environment]::SetEnvironmentVariable("JAVA_HOME", $null, "Machine")

# 设成 JDK 17
[Environment]::SetEnvironmentVariable("JAVA_HOME", "C:\Program Files\Java\latest\jdk-17.0.20.101-hotspot", "Machine")

# 刷新 PATH
$machinePath = [Environment]::GetEnvironmentVariable("Path", "Machine")
$userPath = [Environment]::GetEnvironmentVariable("Path", "User")
[Environment]::SetEnvironmentVariable("Path", "$machinePath;%JAVA_HOME%\bin", "Machine")
[Environment]::SetEnvironmentVariable("Path", "$userPath;%JAVA_HOME%\bin", "User")
```

执行后**必须重开终端**才生效。

验证：

```powershell
java -version   # 应显示 17.0.20.1
$env:JAVA_HOME
```

### 3.2 整理 JDK 目录命名（可选）

当前目录名 `jdk-17.0.20.101-hotspot` 与实际版本 `17.0.20.1` 不一致，
且放在 `latest` 这种通用目录下，以后容易混淆。

建议改名为：

```
C:\Program Files\Java\jdk-17.0.20.1
```

改名后需要同步更新 IDEA 里的 4 处路径配置。

> 不改也不影响使用，只是规范性建议。

## 五、常见后续问题

### 5.1 依赖下载慢/超时

镜像已配好（阿里云），如果仍慢，追加更多仓库：

```xml
<!-- 追加到 ~/.m2/settings.xml 的 <mirrors> 内 -->
<mirror>
  <id>huawei</id>
  <mirrorOf>central</mirrorOf>
  <name>华为云</name>
  <url>https://repo.huaweicloud.com/repository/maven</url>
</mirror>
```

### 5.2 `Unsupported class file major version`

JDK 版本没改干净。检查：
1. Maven Runner JRE（配置 2）
2. 项目 SDK 的 Language level（配置 1）
3. 是不是用了「Maven Importer 的 JDK」这个独立配置（配置 4）

### 5.3 `ClassNotFoundException: javax.xxx`

Lombok 与 JDK 21+ 的兼容问题，JDK 17 下不会遇到。
